# 커밋 메시지 규칙 (#12)

## 형식

```text
<Type>: <이번 변경의 구체적인 내용>

[선택] 변경 이유와 확인한 결과
```

- Type 다음에는 콜론과 공백 하나를 사용합니다.
- 제목에는 바뀐 기능이나 수정 대상을 적습니다.
- 서로 독립된 기능은 나누고, 코드와 그 동작을 검증하는 테스트는 함께 기록할 수 있습니다.
- `수정`, `완료`, `test`처럼 변경 대상을 알 수 없는 제목은 피합니다.
- 아래 예시는 메시지 형식 예시입니다. 실제 이력은 commit-evidence.md에서 구분해 제시합니다.

| Type | 사용 목적 | 형식 예시 |
|---|---|---|
| Feat | 새로운 기능 | `Feat: 목록을 20개씩 표시하는 페이지 이동 기능 구현` |
| Fix | 잘못된 동작 수정 | `Fix: 손상된 저장 파일을 초기화하기 전에 정상 백업 복구` |
| Docs | 설명과 증빙 | `Docs: 커밋 수 증빙과 1000개 데이터 분석 추가` |
| Refactor | 동작을 유지한 구조 개선 | `Refactor: 백업 검증과 파일 교체 책임 분리` |
| Test | 동작 검증 | `Test: 백업 실패 시 원본 파일 보존 검증 추가` |
| Chore | 설정과 관리 | `Chore: backups 폴더를 Git 추적에서 제외` |
| Merge | 브랜치 병합 | `Merge: 보너스 기능 5종 병합` |

## 실제 저장소에 존재하는 예

- `Feat: Quiz 클래스와 문제 출력 및 정답 확인 구현`
- `Feat: 퀴즈 등록과 빈 입력 검증 및 즉시 저장 구현`
- `Feat: 문제별 힌트와 힌트 사용 시 점수 차감 구현`
- `Docs: clone과 pull 실습 완료 과정 및 결과 정리`

## 본문을 포함한 예시

```text
Fix: 손상 파일 보존 후 최신 정상 백업 복구

기존 동작은 손상 시 기본 데이터로 시작해 점수와 기록을 잃을 수 있었다.
변경 후에는 손상 원본을 별도 보존하고 검증된 백업을 최신순으로 탐색한다.
백업 실패 시 원본을 덮어쓰지 않는 테스트를 추가했다.
```
