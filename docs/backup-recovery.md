# 자동 백업 및 복구 정책 (#17)

## 백업 정책

| 항목 | 정책 |
|---|---|
| 주 데이터 | 프로젝트 루트 state.json, UTF-8 |
| 정상 백업 위치 | 프로젝트 루트 backups/state-UTC시각-식별자.json |
| 주기 | 변경된 데이터를 저장하기 직전에 이전 정상 상태 보관 |
| 최초 저장 | 기존 파일이 없으면 처음 저장할 데이터를 초기 스냅샷으로 보관 |
| 기존 파일 최초 사용 | 변경이 없더라도 정상 백업이 하나도 없으면 초기 스냅샷 생성 |
| 같은 데이터 재저장 | 백업이 있으면 불필요한 쓰기와 중복 스냅샷 생략 |
| 정상 백업 보존 수 | 최근 5개. 새 데이터 교체 성공 후 오래된 것 정리 |
| 손상 원본 | backups/corrupt-*.json으로 바이트 그대로 보존 |
| 수동 복원 직전 원본 | backups/before-restore-*.json으로 보존 |
| Git 포함 여부 | state.json, 임시 파일, backups/ 모두 제외 |

자동 백업은 **직전 정상 저장 상태**입니다. 최신 게임 결과가 항상 백업에 들어 있다고 보장하지 않습니다.
최신 상태를 별도 보관하려면 게임 종료 후 `python backup_state.py backup`을 실행합니다.
정상 백업 생성에 실패하면 새 state.json으로 덮어쓰지 않고 실패를 알립니다.
손상 원본 보존 실패 또는 주 파일 읽기 권한 오류가 있으면 그 실행에서는 자동 저장을 차단합니다.

## 자동 복구 순서

1. 시작 시 state.json을 UTF-8로 읽고 스키마를 검증합니다. UTF-8 BOM도 허용합니다.
2. 파일이 손상됐다면 원래 바이트를 corrupt 사본으로 보존합니다.
3. 정상 백업 후보를 파일명의 UTC 시각 기준 최신순으로 검사합니다.
4. 문법/스키마 검증을 통과한 첫 백업을 메모리로 불러옵니다. 손상 백업은 건너뜁니다.
5. 다음 정상 저장 때 복구 내용을 state.json에 반영합니다.
6. 사용 가능한 백업이 전혀 없을 때만 기본 문제 10개와 초기 점수/기록을 사용합니다.

파일 없음도 백업을 먼저 검사합니다. 읽기 권한 실패 시 기본/백업으로 실행할 수 있지만 원본 보호를 위해 그 실행의 저장은 차단됩니다.

## 수동 백업 및 복원 명령어

먼저 실행 중인 게임을 0으로 종료합니다. 실행 중에 복원하면 메모리에 남은 데이터가 종료 시 다시 저장될 수 있습니다.

백업 생성:

```powershell
python backup_state.py backup
```

백업 목록:

```powershell
python backup_state.py list
```

가장 최근의 정상 백업 복원:

```powershell
python backup_state.py restore latest
```

특정 버전 복원은 list에 표시된 실제 파일 이름을 사용합니다.

```powershell
python backup_state.py restore state-실제파일이름.json
```

마지막 명령의 파일 이름은 형식 예시입니다. 그대로 실행하지 말고 list 결과로 바꿉니다.
검증을 통과한 선택 파일만 복원하며, 현재 파일은 먼저 before-restore 사본으로 보존합니다.
복원 후에는 다음처럼 다시 실행하여 목록·점수·기록을 확인합니다.

```powershell
python main.py
```

## 원본 보존과 보존 기간

손상 원본과 before-restore 사본은 실수로 증거를 없애지 않도록 자동 삭제하지 않습니다.
정상 복원과 데이터 확인 후 사용자가 불필요한 사본을 정리합니다. 정기적으로 용량을 확인해야 합니다.
정상 스냅샷은 날짜가 아닌 개수 5개 기준이므로 많이 저장하면 오래된 상태는 빨리 교체될 수 있습니다.
장기간 보존할 상태는 수동 백업 후 프로젝트 밖의 다른 저장 장치에 별도로 복사합니다.

## 한계

- 같은 디스크의 백업은 디스크 고장, 폴더 전체 삭제, 랜섬웨어에 대한 독립 백업이 아닙니다.
- 동일 파일을 여러 게임 프로세스가 동시에 수정하는 것은 지원하지 않습니다. 한 번에 하나만 실행합니다.
- flush/fsync와 임시 파일 교체를 사용하지만 모든 운영체제·하드웨어의 전원 장애 상황을 보장하지 않습니다.
- 백업 기능을 추가하기 전에 이미 소실된 데이터를 되살릴 수는 없습니다.
- 손상 원본 보관은 forensic repair 기능이 아닙니다. 유효한 백업이나 수동 분석이 필요합니다.
